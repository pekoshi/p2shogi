# S13 LZ ROWPF: 行の index が決まった瞬間に先読みを出す

- 状態: 採用 (LZ 段 1 に同梱) / bit 一致: 一致 / requires: S11、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 5.4 節、 6 章 (先読みの教訓)

## 1. 要約

LZ の差分作成で対の index を作った時点で、 その行 (i8 x 64 = 64 B = 1 ライン) を `_mm_prefetch(..., _MM_HINT_T0)` で先読みする。 行を足す (apply) のは差分作成が全部終わった後なので、 その間に読み込みが終わる。 非 PGO 101.84% [101.09, 102.57] (64 周)。

## 2. 前提

- S11 の形: index の列を全部作ってから、 まとめて行を足す。 作る時点と使う時点の間に、 他の計算 (残りの index 作成) がある = リード時間がある。
- 行の表が大きく (我々は群 4 つ x 216,720 行 x 64 B ≈ 55 MB)、 L2/L3 に載らない。

| 一般の言葉 | 本実装 |
|---|---|
| 先読みの関数 | `lz_pf_row(base, row_bytes, idx, hint_t1)` (`p2nnue_lz.h`) |
| 表の先頭と行の大きさ | `Step::pf` / `Step::pf_row` (今の群の表。 i16 の net なら 128 B = 2 ライン) |
| define | `-DP2_LZ_ROWPF=1` (=2 は T1、 =3 はまとめて出す対照) |

## 3. 不変条件

- 先読みは値を変えない。

## 4. 変更の最小単位

1. 差分作成の前に、 今の群の行の表の先頭アドレスと 1 行のバイト数を作業構造体に置く。
2. index を 1 本作るたびに、 2 視点分の行の先頭を T0 で先読みする (行が 64 B を超えるなら 2 ライン目も)。
3. 関門 (M00) と NPS (M00)。

## 5. bit 一致の検証

3 腕 (T0 / T1 / まとめて) とも 49 局面完全一致。 段 1 として G-a / G-b / G-c 全一致。

## 6. NPS の測り方と期待値

| 腕 | 非 PGO、 64 周 |
|---|---|
| **=1 index を作った瞬間に T0** | **101.84% [101.09, 102.57]** |
| =2 同じ位置で T1 (L1 を汚さない) | 100.53% [99.88, 101.20] |
| =3 差分作成の後にまとめて T0 (リード時間 0 の対照) | 100.46% [99.81, 101.12] |

的の大きさ: apply の 553 cycle/評価のうち行の待ちが約 225 cycle (11-11、 先読みで全部の行を温めて測った天井)。

## 7. はまりどころ

- 対照 (=3) が ±0 なので、 効いているのは「先読み」ではなく「リード時間」。 使う直前に出す先読みは効かない。
- 我々の他の先読み (do_move で FT 行、 correction history、 MovePicker、 Finny) はほぼ全滅した。 index が早く決まり、 使うまでに他の仕事がある場所でだけ効く。
- T1 より T0 が良かった (この行は直後に必ず使うので L1 に入れてよい)。
