# S07 fc0 / fc1 の重みを 64 B 境界に置く

- 状態: 採用 / bit 一致: 一致 / requires: M00
- 人間向け: `../SPEEDUPS_STORY.md` 6 章

## 1. 要約

`std::vector<int8_t>` で確保した fc0 の重みが 48 mod 64 の番地に置かれ、 評価のたびに 256 本の split load (キャッシュラインをまたぐ 32 B の load) を出していた。 64 B 整列の allocator に替えて +1.93% [+0.32, +3.76]。

## 2. 前提

- 層の重みを実行時に確保した配列に持ち、 SIMD で 32 B ずつ読む。
- 確保の関数が 64 B 境界を保証していない (`std::vector` の既定の allocator は 16 B 程度しか保証しない)。

| 一般の言葉 | 本実装 |
|---|---|
| 整列の allocator | `AlignedAlloc<int8_t, 64>`、 型 `WsVec` (`p2nnue.cpp:641-662` 付近) |
| 対象 | 本体の fc0 / fc1 の重み、 OPN の同じ層 (`p2nnue_opn.h`) |

## 3. 不変条件

- 重みの値と並びは変えない。 番地だけが変わる。

## 4. 変更の最小単位

1. 重みの番地を確かめる: 読み込み直後に `(uintptr_t)ptr % 64` を stderr に出す。 0 でなければこの仕様が効く。
2. 配列の型を 64 B 整列の allocator を使うものに替える (C++17 の `std::aligned_alloc` か、 `operator new(size, std::align_val_t(64))` を使う allocator)。
3. 手順 1 の出力が 0 になることを確かめる。
4. 関門 (M00)。

## 5. bit 一致の検証

関門 (我々: 89 局面で完全一致)。

## 6. NPS の測り方と期待値

我々: +1.93% [+0.32, +3.76] (局面ごとの対 n=112、 CPU 時間、 profile 同一、 09-29)。 期待値は「split load の本数 x 評価回数」で決まる。 もともと整列していれば 0 (やねうら王の NNUE は各層が `alignas(64)` なので本家には関係ない)。

## 7. はまりどころ

- `std::vector` の番地は確保ごとに変わりうるので、 たまたま整列していた実行と、 していなかった実行で NPS が揺れる。 「NPS が実行ごとに数 % 揺れる」ときはまず番地を出す。
- 整列していない配列は fc0 以外にもありうる (bias、 OPN の層)。 SIMD で読む配列は全部確かめる。
