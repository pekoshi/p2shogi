# S22 L1Q128 の核: fc0 の刻みを 1/128 にして速さを保つ

- 状態: 採用 / bit 一致: net が変わる (旧 net を読む経路は旧 exe と一致) / requires: M00
- 人間向け: `../SPEEDUPS_STORY.md` 8.3 節

## 1. 要約

fc0 の本体 15 行の重みを 1/64 刻みから 1/128 刻みにした (量子化の誤差を減らして篩 +0.0027)。 エンジンでは定数 shift 6 の 30 か所が、 net に応じた変数 shift (6 か 7) になる。 NPS は 99.75% [99.20, 100.32] (64 周、 PGO 同士) で非劣化。

## 2. 前提

- fc0 の出力 = (Σ 入力 u8 x 重み i8 + bias) >> shift。 shift は重みの刻み (QB=64 なら 6)。
- net の重みは f32 の原本 (学習器の `raw.bin`) から量子化し直せる。

| 一般の言葉 | 本実装 |
|---|---|
| 書き直し | python `mk_l1q128.py` (`<tools>/tools/python/net/`): 本体 15 行 x 8 bucket を `clip(round(128 x w), −128, 127)`、 bias を `round(16256 x b)`。 skip 行・fc1・fc2・FT は写すだけ |
| net の印 | arch の 3 番目の token を `AffineTransformL1Q128[16<-2048]` に (旧 exe は読めずに止まる) |
| エンジン | `p2nnue.cpp` の fc0 の後の shift |

## 3. 不変条件

- 旧 net (刻み 64) を新 exe で読むと、 旧 exe と同じ値。
- 新 net を新 exe で読むと、 python の整数推論と同じ値。
- skip 行 (16 本目) の刻みは変えない。

## 4. 変更の最小単位

1. エンジン: fc0 の後の shift を、 net の arch の印から決める変数にする。
2. 中間検査: 旧 net を新 exe と旧 exe で読ませて関門 (M00) が一致。
3. net の書き出し: 自己検算 (現行の式で刻み 64 を作り直すと元と全バイト一致) → 刻み 128 で書き出し。 飽和の本数を数える (我々は 122,880 本中 13 本。 桁違いに多ければ止める)。
4. 照合: 新 exe の静的評価と python の整数推論が全局面で一致 (我々は 130,965 局面で不一致 0)。

## 5. bit 一致の検証

新 exe + 旧 net、 新 exe + 新 net (対 python) とも不一致 0。 旧 exe と新 exe の探索が 4/4 局面で一致 (旧 net)。

## 6. NPS の測り方と期待値

我々: 99.75% [99.20, 100.32] (64 周、 PGO 同士、 旧 net 対 新 net)。 別の測定で税 +0.25% [−0.32, +0.81] (256 対)。 定数 shift が変数 shift になっても差は見えない。

## 7. はまりどころ

- bias の刻みも重みに合わせて変える (128 x 127 = 16256)。
- 丸めは 0 から遠い方 (学習器の Rust `f64::round` と同じ)。 python の `round` は偶数丸めなので使わない。
