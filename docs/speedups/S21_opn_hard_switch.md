# S21 2 本の net の継ぎ目を幅 0 に (混ぜる区間をなくす)

- 状態: 採用 (v9 の既定 `OPN_ProgHi=-1946` / `OPN_ProgWidth=0` / `OPN_LambdaMax=256`) / bit 一致: **値が変わる** / requires: S19
- 人間向け: `../SPEEDUPS_STORY.md` 8.2 節

## 1. 要約

序盤専用の net (OPN) と本体を、 進行度の区間で λ を変えて混ぜていた。 混ぜる区間では両方を計算するので遅い。 区間の幅を 0 にして、 境の手前は OPN だけ・後は本体だけにした。 1 手 1 秒の到達ノードが 対 v4 で 106.1% → 110.0% [108.0, 112.0]。

## 2. 前提

- 2 本の net を進行度で切り替える構成。 片方だけを計算する局面では、 もう片方の accumulator も作らない (λ=256 なら本体と threat を計算しない)。

| 一般の言葉 | 本実装 |
|---|---|
| 境 | `OPN_ProgHi` (進行度 x 1000) |
| 混ぜる区間の幅 | `OPN_ProgWidth` (0 = 混ぜない) |
| 混ぜる強さの上限 | `OPN_LambdaMax` |
| 目盛り | `OPN_Scale0..2` (bucket 0〜2 ごとに OPN の出力に掛ける Q10 の係数) |

## 3. 不変条件 (質の線)

評価値は変わるので、 bit 一致ではなく「質を落とさない」ことを線にした: 境での評価値の跳ね (前後の比) <= 1.05、 篩の差 >= −0.003。

## 4. 手順

1. 幅を 0 にした設定で、 境をはさむ局面の評価値の跳ねと、 篩 (静的評価の質) を測る。
2. 1 手 1 秒の到達ノード (対局の枠で、 相手と同じ局面) を測る。
3. 対局で確かめる (我々は仮対局 50 局で誤差の内、 以後の基準にした)。

## 5. 検証

質の線は通過。 対局は 50 局の仮対局で 21-27-2 (44.0%、 その前の設定 42.0% と誤差の内)。

## 6. 期待値

我々: 1 手 1 秒の到達ノード 対 v4 g3_b 107.7% [104.6, 110.9] (それまで 101.9%)、 全 64 局面 110.0% [108.0, 112.0] (それまで 106.1%)。 2 周、 PGO exe。

確認対局の設定: `OPN_ProgHi=-1299` / `OPN_ProgWidth=0` / `OPN_LambdaMax=256` / `OPN_Scale=1196,1204,1377`。 v9 では継ぎ目を `OPN_ProgHi=-1946` に下げ、 OPN は進行度 bucket 0 だけを受け持ちます (幅 0・LambdaMax 256 は同じ)。 目盛りの既定は `OPN_Scale0=1196` (bucket 0 しか OPN を使わないので、 Scale1 / Scale2 は実際には効かない)。 配布直前の sweep は行っていません。

## 7. はまりどころ

- 幅 0 では OPN と本体が混ざらないので、 本体を替えたときに OPN の目盛り (Scale) を取り直す必要は小さい (我々は L1Q128 の後も据え置いた)。 混ぜる設定に戻すなら取り直す。
- 幅 0 の境では、 OPN の帯から本体の帯へ移る node で threat の accumulator の基点が無くなり、 全計算が増える (S25)。
