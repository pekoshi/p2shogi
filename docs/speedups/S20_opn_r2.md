# S20 OPN R2: 命令レベルの 7 項目 (G8 核・本数固定の核・refresh の融合)

- 状態: 採用 / bit 一致: 一致 / requires: S19、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 8.2 節
- 本家への提案: `../UPSTREAM_PROPOSALS.md` P3 (G8)、 P4 (融合)、 P5 (本数固定)

## 1. 要約

S19 の後に残った命令レベルの無駄を削った。 f5 比 +2.1% [0.1, 4.1] (非 PGO) / +2.0% [0.2, 3.9] (PGO 同士)。 rdtsc で OPN の評価 −640〜−720 cycle (−8〜9%)、 本体 −190〜−390 cycle。

## 2. 前提と項目

| 項目 | 中身 | 効いた量 (rdtsc) |
|---|---|---|
| R2-1 G8 核 | fc0 (AVX2・VNNI なし・密) で、 `maddubs` (u8 x i8 → i16 の対の和) の結果を i16 のまま 8 chunk 分足してから `madd` (i16 → i32) を 1 回。 i16 が溢れないことを**読み込み時に重みから確かめた** bucket (head) だけで使い、 満たさない head は従来の経路 | OPN の fc0 + 後段 −244〜−393 cycle。 本体 (幅 1024) では −14 = 差なし |
| R2-2a/b/c 本数固定の核 (OPN) | 引く行・足す行の本数が同じで 1〜4 本のとき、 行ポインタをループの外でレジスタに置いた核 `r2_rows_fx<N>` で作る | −22〜−235 cycle |
| R2-2d 本数固定の核 (本体) | 同じ核を本体の差分更新にも | 本体の acc −61〜−253 cycle |
| R2-3 refresh と transform の融合 | Finny の refresh の最後の列ループで transform まで書く | refresh 側 −65〜−120 |
| R2-4 refresh のループの形 | 64 列ごとに 4 レジスタ、 行を内側に (従来は 16 列ごとに全行) | 本体の acc −60〜−100 |
| P1 出力数を定数に | `affine_par` の出力数をコンパイル時定数に (実行時の値だと累算器がメモリに落ちる) | chunk 1 個 約 10 cycle の依存鎖を解消 |

### G8 の安全条件

maddubs の 1 要素は `u8*i8 + u8*i8` で、 入力は 127 以下 (従来の maddubs の飽和条件と同じ前提。 transform の出力は 254x254>>9 = 126 以下)。 8 chunk 足すと i16 を超えうるので、 maddubs の lane (出力 o、 chunk 内の前半 / 後半) ごとに「入力が最大のときの 8 chunk ぶんの部分和」が i16 に収まるかを読み込み時に重みから全部確かめ (`affine_g8_safe`)、 収まる head だけ G8 を使う。 部分和が i16 に収まれば、 i16 の加算は溢れず、 整数の和として従来と同じ (足す順が違うだけ)。 先読みは足さない (この形では先読み無しが最良。 2 KB 先で +130 cycle)。

## 3. 不変条件

- G8: 安全条件を満たす head では i16 の和が溢れないので、 i32 で足すのと同じ値。 満たさない head は従来の経路。
- 本数固定の核: 足す順序が変わるだけ (i16 の wrapping 加算は可換)。
- 融合: transform の式は同じ。

## 4. 変更の最小単位

1. P1 (定数化) → R2-2 (本数固定) → R2-4 → R2-3 (融合) → R2-1 (G8) の順。 1 項目ごとに静的評価の全一致と探索の一致。
2. G8 は安全条件の検査を先に書き、 「どの head が G8 を使ったか」を起動時にログに出す。
3. 全部入れたら M00 の NPS。

## 5. bit 一致の検証

探索 32 局面 depth 18 が 12 設定で 32/32、 静的評価 32,742 局面 x 3 設定が全一致、 G8 の自己検査 selfcheck_ng=0。 R2 を外した exe は f5 と逆アセンブルが同一 (define を外せば従来のコードに戻ることの確認)。

## 6. NPS の測り方と期待値

我々: f5 比 +2.1% [0.1, 4.1] 非 PGO / +2.0% [0.2, 3.9] PGO 同士 (64 局面 x 50 万ノード、 置き換え)。 OPN を使わない本体だけの exe どうしで f5 比 101.1% [99.5, 102.7] (R2-2d と R2-4 の分)。 幅 1024 で fc0 の入力が 256 chunk の本体では G8 は効かなかった (−14 cycle)。 幅 2048 以上で効く。

## 7. はまりどころ

- G8 を本体 (幅 1024) に当てても差なし。 効くのは fc0 の積和の比重が大きい幅の広い net。
- 本体の fc0 に先読みを足す・PSQT 行を後回しにする・親の作成と子の更新を融合する、 は差なしか悪化 (`REJECTED.md` R28)。
