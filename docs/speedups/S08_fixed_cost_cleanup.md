# S08 評価と探索の固定費を削る束 (A1〜A3 / 束 P2 / 束 A345)

- 状態: 採用 / bit 一致: 一致 / requires: M00
- 人間向け: `../SPEEDUPS_STORY.md` 6 章

## 1. 要約

評価関数の 1 回ごとに払っていた小さな固定費を消す束。 効いたのは A3 (`__chkstk` の除去) を含む A1〜A3 で、 束で中央 +4.81% (壁時計、 8 round、 非 PGO)。 他の項目 (束 P2・A345) は有意な得なしで、 コードの整理として入れた。

## 2. 前提と項目

| 項目 | 一般の言葉 | 本実装 |
|---|---|---|
| **A3** | Win64 では 4 KB を超える関数のフレームの入口で `__chkstk` (mingw では先頭の `_` が 3 つの `chkstk_ms`) が呼ばれ、 スタックを 1 ページずつ触る。 熱い関数のフレームを 4 KB 未満にすれば消える | 多段の差分更新 `ensure_perspective` の作業配列 `chain[300]` → 128 (フレーム 4.7 KB → 3.3 KB、 毎評価 2 回の呼び出しが消えた)。 `noinline` で 2 重の inline を防ぐ |
| A1 | 使わない accumulator を priming で作らない | threat の差分が無効な net では priming で threat acc を作らない |
| A2 | 既に計算した値を使い回す | threat の群の表の offset を、 既に計算した bucket から引く |
| 束 P2 (a) | 重み 0 の補正表を読まない | hand 補正の読み出しをガード |
| 束 P2 (b) | 関数内の static な getenv 判定を消す | 計測用スイッチの後始末 9 か所 |
| 束 P2 (c) | 素のグローバルを thread_local に | `g_in_qsearch` (潜在的なデータ競合の修正を兼ねる) |
| A345 | transform の store の半減 / 差分ループの 4 レジスタ展開 / getenv 25 個の除去 | 🚨transform の store 半減は現行の本体の transform に残っていない (経緯は未確認。 同じ発想は final2 の F01 で入れ直した) |

## 3. 不変条件

- どの項目も計算の値を変えない。 A1 は「その accumulator を読む経路が無い」ことが前提 (読む経路があるなら作る)。
- A3: 配列の上限を下げたら、 上限を超える場合は従来の全計算 (Finny など) に落ちること (値は変わらない、 費用だけが変わる)。

## 4. 変更の最小単位

1. **A3 の当否を測る前に確かめる**: 熱い関数を逆アセンブルし、 入口で `__chkstk` (mingw では先頭の `_` が 3 つの `chkstk_ms`) を呼んでいるかを見る。 clang なら `-Wframe-larger-than=4096` で警告が出る。
2. 呼んでいれば、 その関数の大きなローカル配列を小さくする (上限超えは従来の経路に落とす) か、 配列を thread_local / 呼び出し側の固定の領域に移す。
3. 手順 1 で呼び出しが消えたことを確かめ、 関門 (M00)。
4. A1・A2 は、 profile (perf / VTune) で priming の中の不要な計算を見つけたら同じ手順で。

## 5. bit 一致の検証

全周 nodes 一致 (A1〜A3 の束で 7,002,043 ノード)、 対局の sanity。 束 P2 は 89 局面で完全一致。

## 6. NPS の測り方と期待値

A1〜A3: 中央値 +4.81% (壁時計、 8 round、 1M x 8 局面、 非 PGO、 09-15)。 🚨当時の器は壁時計で、 今の基準 (M00) より粗い。 A3 単独の値は無い。 束 P2: +0.06% [−0.62, +0.75] (n=12) = 差なし。 A345: 判定行が残っていない。

## 7. はまりどころ

- `__chkstk` は 4 KB 超のフレームだけで出るので、 配列の上限を少し変えただけで出たり消えたりする。 別の高速化で配列を足したら確かめ直す (LZ の対の配列 256 x 4 x int = 4 KB で同じ問題が出た。 S17 は NPS が出ず不採用)。
- getenv の static ガードは「1 回しか評価されないので安い」と思いがちだが、 熱い関数の中ではガード変数の読み出しと分岐が残る。
