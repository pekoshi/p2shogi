# S03 threat の出力幅を 64 列に絞る

- 状態: 採用 / bit 一致: **net の形が変わる** (同じ net を幅 K で読む経路どうしは一致) / requires: M00
- 人間向け: `../SPEEDUPS_STORY.md` 1 章

## 1. 要約

大きな疎入力 (threat 216,720 次元) の出力を、 FT の全幅 1024 列ではなく 64 列だけにする。 1 行が i8 x 64 = 64 B = 1 キャッシュラインになり、 accumulator の加減算の費用と行の読み込みがほぼ消える。 税 −37.5% (K=1024) → −17% (K=64)。 net を学習し直す必要がある (lossless ではない)。

## 2. 前提

- 主入力 (HalfKA など) の FT とは別に、 大きな疎入力の accumulator を持ち、 その出力を FT の出力に足している。
- 疎入力の 1 回の評価で触る行が多い (我々は 1 評価 61 行)。

| 一般の言葉 | 本実装 |
|---|---|
| 疎入力 | threat (profile 0)、 `p2nnue_threat.h` |
| 出力幅 K | `-DP2_THREAT_OUT=64`、 `THREAT_ACC_DIM` |
| 足す位置 | 前半 K/2 を FT の [0, K/2)、 後半 K/2 を [512, 512+K/2) |

## 3. 不変条件

- K = FT の全幅なら従来と完全一致 (入れ子のモデル)。
- 足す位置は FT の「対の積」の両側に対称に置く。 transform が `out[j] = clamp(acc[j]) * clamp(acc[j+512])` なので、 片側にだけ足すと、 もう片側に threat が乗らない非対称な構造になる。

## 4. 変更の最小単位

1. 学習器: 疎入力の出力幅を引数にする (`--threat-out 64`)。 出力を FT の前半・後半の先頭 K/2 列に足す。
2. エンジン: 疎入力の accumulator の列数を K にする (コンパイル時定数)。 transform で FT の該当列に足す (`transform_pair_sum`)。
   - 中間検査: K = 1024 でビルドし、 従来の exe と関門 (M00) が全一致。
3. K = 64 の net を学習し、 K = 64 でビルドしたエンジンで読む。
   - 中間検査: エンジンの静的評価と学習器 (python) の整数推論が全局面で一致。

## 5. bit 一致の検証

同じ net を読む経路の一致は手順 2 の中間検査で。 K を変えた net は別物なので、 強さは対局か篩で判定する (我々は K の掃引の後、 K=64 の net を採った)。

## 6. NPS の測り方と期待値

我々の 9 月の単発の測定 (区間なし): 税 K=1024 −37.5% / 512 −32.0% / 256 −24.8% / 64 −17%。 列挙 (どの対が立っているかを作る部分) の −13.6% は K に依らず残る。 K を減らしても列挙は減らない。

## 7. はまりどころ

- K を絞るほど速いが、 net の表現力は落ちる。 我々は K の掃引の NPS と篩で 64 を選んだ。 全幅の threat を速く回せるかは未踏の問い (`../FUTURE_WORK.md` 3 章)。
- 群化 (bucket ごとに別の表) と組み合わせると表の総量は増えるが、 1 評価で触る行の数は変わらない。
