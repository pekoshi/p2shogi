# S16 LZ D1FAST: 1 手分の差分 (d=1) の専用路

- 状態: 採用 (NPS は測らずに採用。 ユーザー判断) / bit 一致: 一致 / requires: S11、 S12、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 5.4 節

## 1. 要約

LZ の差分は評価の 75% が d=1 (親が valid) で、 その費用 2,146 cycle のうち約 683 cycle は「盤の作業用の写し (81 升 + 駒種の bitboard 14 本) を作る」「最後に不要な undo をする」などの固定費だった。 d=1 のときは写しを作らず、 今の局面 (Position) を直接読んで Δ を作る。

## 2. 前提

- S11 の差分作成が、 多段 (d>=2) のために盤の写しを作り、 1 手ずつ undo しながら Δ を作る形になっている。
- d=1 では巻き戻しが要らない: 「動いた後の局面」は今の局面そのもので、 「動く前」は今の局面と直前の手 (動いた駒・元の升・取った駒) から分かる。

| 一般の言葉 | 本実装 |
|---|---|
| 盤の写し | `ScratchView` (`v.init(pos)`) |
| 今の局面を読む view | `PosView{pos}` |
| 1 手の Δ | `build_step(view, tot, A, B, p_before, p_after, cap, nrm_b, nrm_w)` |
| define | `-DP2_LZ_D1FAST` |

## 3. 不変条件

- d=1 の経路が作る ADD / SUB の列は、 写しを使う経路と同じ (順序も含めて同じでなくてもよいが、 多重集合として同じ)。
- `p_after = pos.piece_on(B)`、 `p_before = make_piece(color_of(p_after), 動く前の駒種)` (打つ手なら無し)。 写しの経路と 1 文字も違えない。
- null move の子は Δ=∅ (ADD・SUB とも 0 本) のまま進み、 基点の写しと valid の書き込みだけが走る。
- 行の先読み (S13) の設定は分岐の前に置く。

## 4. 変更の最小単位

```
#if defined(P2_LZ_D1FAST)
  if (d == 1) {
      tot.mark(0);
      if (!steps[0].nul) {
          PosView pv{pos};
          build_step(pv, tot, A, B, p_before, p_after, cap, nrm_b, nrm_w);
      }
  } else
#endif
  { ScratchView v; v.init(pos); build_chain(v, tot, steps, d, nrm_b, nrm_w); }
```

1. 上の分岐を足す。 `build_step` が view の型に対してテンプレートになっていること (写しと生の局面の両方を受ける)。
2. 検算 `LZ_VERIFY`: 差分で作った直後に全計算を別の buffer に作り、 両視点の全列を比べる。 5 局面 x 20 万で不一致 0。
3. 関門 (M00) の G-a / G-b / G-c。

## 5. bit 一致の検証

検算と関門 3 本がすべて一致。

## 6. NPS の測り方と期待値

設計の判定線は「段 1 の exe 比で CI 下限 > 100% かつ 点 >= +1.0%」。 🚨計測は対局と重なって中断し、 採用はユーザー判断で NPS を測らずに行った。 公開版に入っているが、 単独の得の判定行は無い。 的の大きさ: d=1 の固定費 約 683 cycle (評価 1 回 8,867 cycle の約 7.7%、 d=1 は評価の 75%)。 期待値は +1〜3% (推測)。

## 7. はまりどころ

- 写しの経路と、 動く前の駒・取った駒の作り方を変えないこと (成り・打つ手・取りの組み合わせ)。 差が出るのは稀な手なので検算で全件を見る。
- 計測用の rdtsc (probe) を d>=2 側にだけ残すと、 d=1 の費用が見えなくなる。
