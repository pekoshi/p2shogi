# S25 LZ BACKMAT: 全計算に落ちたら親へ逆向きに物質化する (`P2_LZ_BACKMAT`)

- 状態: **不採用** (probe の関門は通過 / 検算 不一致 0 / 関門 完全一致 / NPS は線に届かず。 公開版のソースには入れていない) / bit 一致: 一致 / requires: S11、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 5.5 節

## 1. 要約

LZ (S11) で基点の祖先が見つからず全計算に落ちた node は、 自分にしか結果を書かないので、 同じ親の次の子もまた全計算になる。 全計算の直後に、 今の accumulator から 1 手分の Δ を**逆向きに**適用して親の accumulator を作り、 親を valid にする (最大 K 手上まで)。 次の兄弟は d=1 で済む。 上限は約 +2.2%、 見込み +0.8〜1.6% (推測)。

## 2. 前提

- S11 の差分作成 (1 手の Δ = ADD / SUB の列) がそのまま使える。
- 全計算に落ちる node が同じ親の下で続く状況がある。 我々では、 2 本目の net (OPN) の帯では本体も threat も計算しないので、 root が OPN の帯にある探索で、 本体の帯へ移る node が基点を持たない。 5M ノードあたり全計算 392,642 回で、 そのうち 315,320 回が「64 手遡っても同じ群の valid な祖先が無い」。

## 3. 不変条件 (書いてよい条件。 1 つでも外れたらそこで止める)

1. 親の両視点が invalid (valid な node には一切書かない = S11 の規則)。
2. 親の鏡像が今と両視点とも同じ (玉を巻き戻して判定)。
3. 子がその thread の root の状態ではない (root より上は thread 間で共有される履歴なので書かない)。
4. 対が上限を超えていない。
5. bucket・進行度を新たに計算しない (S11 の不変条件 4)。

bit 一致の根拠: `acc(親) = acc(子) − ADD(親→子) + SUB(親→子)`。 i16 の wrapping 加算は可換・結合的で、 減算は加算の厳密な逆元なので、 親で全計算した値と 1 bit も違わない。 書く群は今の群。 親が後で別の群で評価されても、 既存の群一致の検査が invalid として作り直す。

## 4. 変更の最小単位

1. 全計算の直後に、 1 手分の Δ を作る (S11 / S16 の build_step) → 逆向きに適用して親に書く関数を足す。 K 手まで繰り返す (`-DP2_LZ_BACKMAT=<K>`、 1 <= K < DMAX)。
2. probe (計測ビルド) で、 全計算の回数と d=1 の回数の変化を K = 1, 2, 4 で数え、 K を選ぶ (NPS の前の関門)。
3. 検算 `LZ_VERIFY` を、 逆向きに作った親の acc にも適用 (親で全計算を別に作って比べる)。
4. 関門 (M00)。

## 5. bit 一致の検証

検算 `P2_LZ_VERIFY` を K=1/2/3 (10 局面 x 20 万ノード) と K=1 Threads 4 (移り目 5 局面 x 100 万ノード) で回し、 不一致 0 (逆向きに作った親を基点にした検算 43,820〜90,558 回を含む)。 関門は G-a / G-b / G-c x INFREP off/on の 6 本すべて完全一致。

## 6. NPS の測り方と期待値

効くのは root が OPN の帯から本体の帯へ移る局面だけで、 標準の NPS 4 局面では検出できない (効く局面は多くて 1 つ)。 判定は移り目の 5 局面で、 線は「点 +1.0% 以上かつ CI 下限 > 100%」(事前固定)。 probe (非 PGO、 移り目 5 局面) では threat の総 cycle が K=1 で −16.4% (全計算の割合 38.7% → 8.0%)、 中盤 5 局面では −5.9%。 NPS の A/B (PGO 同士) は 14 周で打ち切り、 100.19% (区間なし) で線に届かず、 不採用としました。

## 7. はまりどころ

- root の priming で threat を作る案は単独では効かない (root から移り目までの途中の node が全部 invalid のままなので)。
- 全計算は「何を書いたか」を祖先に伝えない。 差分経路だけでなく全計算の経路にも物質化の機会がある、 という見落とし。
