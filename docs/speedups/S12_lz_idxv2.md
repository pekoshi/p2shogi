# S12 LZ IDXV2: 対の index 計算を攻め駒ごとにまとめる

- 状態: 採用 (LZ 段 1 に同梱) / bit 一致: 一致 / requires: S11、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 5.4 節

## 1. 要約

LZ の差分作成 (build) の中で、 対 1 本ごとに攻め駒側の値 (種類・色・攻撃のパターン・正規化した升・表の行の先頭) を引き直していたのを、 攻め駒ごとに 1 回だけ作り、 標的ごとには列の番号と順位だけを足すようにした。 非 PGO 102.27% [101.63, 102.93] (64 周)。

## 2. 前提

- S11 の差分作成で、 同じ攻め駒 X が 1 手の中で何度も現れる (自分が動いた / A・B に利いている / 飛び駒の 2 つのループ / 歩み駒の 2 つのループ)。
- 対の index が「攻め駒側の部分 + 標的側の部分」の和で書ける。 我々の形:

```
index(視点 b) = pair_base[攻め駒の色・種類][標的の色・種類]
              + from_offset[pattern(攻め駒の種類・色)][正規化した X の升]
              + attack_order[pattern][正規化した X][正規化した T]    (X の利き升の中で T が何番目か)
```

| 一般の言葉 | 本実装 |
|---|---|
| 1 対ごとの index 作成 | `lz::emit` (`p2nnue_lz.h`) |
| 攻め駒側の前計算 | `AttCtx`、 `emit_v2` |
| 標的の種類 → 列 | 表 `g_tgt_key` (駒 32 種 → 列 `dsb*9+dc`、 玉・空は −1) |
| define | `-DP2_LZ_IDXV2=1` (=2 は順位を popcount で出す変種。 劣ったので不採用) |
| 検算 | `-DP2_LZ_IDXV2_VERIFY` |

## 3. 不変条件

- 出る index の値と順序は従来の emit と 1 bit も違わない (ADD / SUB の列が同じ)。

## 4. 変更の最小単位

1. 攻め駒 X ごとに、 視点 2 つ分の `pair_base` の行ポインタ、 `from_offset` の値、 `attack_order` の行ポインタ (= 正規化した X の行) を構造体に作る関数を足す。
2. 標的 T ごとには、 表から列 (`kb` / `kw`、 −1 なら対にしない) と、 正規化した T の升による順位だけを引いて足す関数 (emit_v2) を足す。
3. 差分作成の全ループで、 X が決まった所で手順 1 を 1 回呼び、 内側のループを emit_v2 に替える。
4. 検算: 新旧の index を同じ exe で両方作って比べる (`IDXV2_VERIFY`)。 5 局面 x 20 万で不一致 0。
5. 関門 (M00)。

## 5. bit 一致の検証

検算 pairs=457,217 / mismatch=0 (11-16、 本番 option)。 関門 49 局面 完全一致 (11-11)、 段 1 として G-a / G-b / G-c 全一致。

## 6. NPS の測り方と期待値

我々: 非 PGO 102.27% [101.63, 102.93] (64 周、 OPN 導入前)。 =2 (順位を popcount で出して 92 KB の表を引かない) は 101.53% [100.88, 102.21] で劣った。 PGO での単独値は測っていない (段 1 の束として S15 = +4.19%)。 的の大きさ: 差分作成 1,568 cycle/評価のうち index 計算が約 589 cycle (11-11 の rdtsc)。

## 7. はまりどころ

- 表を popcount に替える (=2) と、 表引きが消える代わりに命令が増えて遅くなった。 表が L1/L2 に載っているなら表のほうが速い。
- 前計算の構造体がスタックを大きくして `__chkstk` を呼ばせないか確かめる (S08)。
