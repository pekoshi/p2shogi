# F03 本体の fc0 の重みを先読みする (`P2_FC0_PF`)

- 状態: **採用** (final2。 関門 完全一致 / NPS は F01〜F03 の合計で 101.74%、 区間なし) / bit 一致: 一致 (先読みは値を変えない) / requires: S07、 M00
- 人間向け: `../SPEEDUPS_STORY.md` 6 章
- 出どころ: OPN の F2-1 (`S19_opn_f2.md`)。 OPN では fc0 + 後段 −15〜17% (rdtsc、 幅 1024 と 2048 の両方で)

## 1. 要約

密な fc0 の積和 (入力 4 byte を broadcast → maddubs → madd) のループで、 重みを 2 KB 先まで `_mm_prefetch` する。 LayerStack が 8 bucket あると、 bucket ごとの fc0 の重み (16 KB) が L1 から落ちやすく、 評価のたびに読み直しになる。

## 2. 前提

- 密な fc0 (`affine_par` と同じ式・同じ順)。 重みは 64 B 整列 (S07)。
- bucket ごとに別の重み (LayerStack)。

| 本実装 | 場所 |
|---|---|
| 核 | `affine_pf_t<FC0_WS_ROWS, P2_FC0_PF_BYTES>` (`p2nnue.cpp`) |
| define | `-DP2_FC0_PF` (`P2_FC0_PF_BYTES` 既定 2048) |

## 3. 不変条件

- 積和の式と順序は `affine_par` と同じ。 先読みを足すだけ。

## 4. 変更の最小単位

1. `affine_par` の写しを作り、 ループの各 chunk で `PFB` byte 先の重みを `_MM_HINT_T0` で先読みする。
2. 本体の fc0 の呼び出しを写しに替える (AVX2 のときだけ)。
3. 関門 (M00)、 NPS (M00)。 先読みの距離 (1 KB / 2 KB / 4 KB) を振るなら rdtsc の器で。

## 5. bit 一致の検証

関門 (G-a / G-b / G-c x INFREP off/on) はすべて完全一致。

## 6. NPS の測り方と期待値

M00。 🚨OPN の G8 核 (S20) では「先読み無しが最良」で、 先読みを足すと +130 cycle 悪化した。 本体の fc0 は G8 を使わない (幅 1024 では効かない) 密な経路なので、 F2-1 と同じ形で効く見込みだが未測定。 また 11-15 の試験で「本体の fc0 を G8 に / 本体の差分更新に行の先読み」は差なしだった (`REJECTED.md` R28)。 結果: 3 本 (F01〜F03) を一緒に入れた exe で 28 周で打ち切り、 101.74% (区間なし、 3 本の合計。 単独の値はない)。

## 7. はまりどころ

- 先読みの距離は核の形で最良が変わる。 OPN の密な核では 2 KB、 G8 核では 0。
- 重みが L1 に載り続ける構成 (bucket が少ない、 評価が連続して同じ bucket) では効かない。

## 8. 根拠

実験記録 (設計書・事前登録・判定ログ) は非公開です。 関連: OPN 側の同じ核は `S19_opn_f2.md` (F2-1)。
